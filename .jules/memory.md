- In `build123d` (`src/housing.py`), `Housing_Pump_Lid` features a continuous solid top face (without a center pass-through hole) and an attached bottom indexing lip positioned to overlap slightly into the main lid body, producing a single contiguous solid.
- Standardized 4-electrode sensing terminology across the codebase and documentation is: `WS_CIS` (Working Sense), `WE_POS` (Working Electrode Positive), `RE_TRANS` (Reference Electrode Trans), `CE_GNDA` (Counter Electrode Ground), and `GUARD`.
- The canonical project name is 'MR1'. Legacy terms like 'Sentinel', 'Daemon Pore', or 'daemon-pore' have been universally replaced. Specific casing conventions apply: UPPER_CASE or PascalCase contexts use 'MR1', while snake_case, kebab-case, camelCase, and filenames use 'mr1'.
- KiCad BOM and Gerber export tests (e.g., `test_interposer_bom_completeness`, `test_interposer_gerber_exports`) are intentionally skipped and tracked in `TODO.md` pending robust CI support for the `kicad-cli` toolchain.

- `install.sh` checks for PlatformIO in `.venv`, system `PATH`, and via `python -m platformio`, automatically installing `platformio` into `.venv` via `pip` if missing. `scripts/export_manager.py` prioritizes finding `pio` inside `.venv` before checking system `PATH`.
- The `Torque_Cap_Outer` 6 cantilever flexure arms (tongs) use a compliant 1.8 mm PETG living hinge thickness with 2.5 mm root fillets and 1.5 mm radius pawl tips ($R = 38.7\text{ mm}$), tuned to deliver a slip torque limit of $\approx 0.5\text{ N}\cdot\text{m}$ ($F_{\text{clamp}} \approx 33.3\text{ N}$) to compress the 12 pogo pins (~9.6 N total load) and seat the silicone gasket without over-tightening.
- The repository includes a formal verification suite in `tests/test_formal_proofs.py` using `z3-solver` and `hypothesis` to prove SMT theorems and property-based invariants across firmware/protocol logic, physics/analog front-end, geometric/CAD layout, microfluidics, electrokinetics, pump ESTOP safety logic, DAQ stream framing, firmware state machine, and electrical harness pin mapping, integrated directly into `run_tests.py`.
- In `imageio.mimsave`, setting `macro_block_size=1` prevents image width/height padding warnings when exporting 1080p VP9 WebM videos.
- Readout route selection on the MR1 Nanopore Reader uses `PIN_ROUTE_SEL` (GPIO2) to control the `U17` SPDT switch between Route 1 (10 GΩ gain, LMP7721, `ROUTE_SEL` LOW) and Route 2 (100 kΩ gain, OPA2192, `ROUTE_SEL` HIGH). Firmware protocol uses `STATUS_ROUTE2_ACTIVE = (1 << 7)`, commands `SET:ROUTE:<1|2>` and `GET:ROUTE`, `/api/route` HTTP API, and `daq_client.py` auto-adjusts transimpedance gain dynamically from stream telemetry.
- Execute environment setup using `bash ./setup_env.sh` rather than direct execution (`./setup_env.sh`) to prevent permission denied errors.
- The repository includes KiCad projects such as 'Amplifier' and 'MR1'. Auto-generated `.history` directories within these project folders are appropriately ignored via `.gitignore` and must never be tracked as git submodules.
- On the MR1 Interposer, microfluidic Cis flow connects H1 to H2 and Trans flow connects H3 to H4. Standard interposer electrode footprints use `Electrode` and `Electrode_Guard`, while pogo pin target landings default to `PogoPin_Target_Landing_1Pin` (or `PogoPin_Target_Landing_1Pin_Guarded` for High-Z/guard nets).
- In `Interposer/Interposer.kicad_sch` and `Interposer/Interposer.kicad_pcb`, mounting/fluid holes `H1`, `H2`, `H3`, `H4` are defined using `Mechanical:MountingHole` symbols with `Value: FluidHole` and `Footprint: MountingHole:MountingHole_2.1mm`.
- The MR1 Main Controller Board PCB is a 4-layer FR4 design with split ground planes (GNDA and GND on Layer 2) and split power planes (VDDA/VSSA and 3V3/VBUS on Layer 3), driven by an ESP32-S3-MINI-1U microcontroller.
- When calling shape-generating helper functions inside an active `BuildPart` context, encapsulate helper shape construction inside `with BuildPart(mode=Mode.PRIVATE)` to prevent intermediate untapered or raw geometries from automatically merging into the parent context.
- The distributed 2 x 6 pogo pin layout divides pins into Bank B (Cis / High-Z Sensing, Y > 0) and Bank A (Trans / Excitation & Fluid Drain, Y < 0) across X = -18 mm to +18 mm to distribute mechanical spring loads across the 55 mm x 52 mm hexagonal envelope and isolate high-amplitude excitation drive from high-Z sensing nodes.

It batches 16 USB frames by default (1024 samples per message, 4104 bytes total @ ~97.66 Hz, configurable via `--batch-frames`).
