## Reporting a Vulnerability

The Sentinel Nanopore Reader team takes security and hardware electrical safety seriously. If you discover a security vulnerability or critical hardware safety defect, please follow responsible disclosure practices.

### How to Report

1. **Do not disclose publicly**: Please **do not** report security vulnerabilities or safety defects via public GitHub issues, discussions, or social media.
2. **Submit via GitHub Private Vulnerability Reporting**: Use the **Security** tab on the repository and click **Report a vulnerability**, or contact the maintainers directly through the repository administrators.
3. **Include Details**:
   - Component affected (e.g., ESP32-S3 firmware, Web portal, USB CDC stream, or hardware power circuits)
   - Step-by-step reproduction instructions or proof-of-concept (PoC) code
   - Expected behavior vs. actual behavior
   - Assessment of potential impact (e.g., remote execution, buffer overflow, hardware electrical overstress)

### Response Timeline

- **Initial Acknowledgement**: Within 48 hours of receipt.
- **Triage & Assessment**: Within 5 business days, confirming whether the report represents an actionable security issue.
- **Remediation & Patching**: We will release a coordinated fix along with a security advisory detailing credit to the reporter (unless anonymity is requested).

## Hardware Safety & Electrical Considerations

The Sentinel Nanopore Reader controls sensitive microfluidics and precision analog electronics:

1. **Electrode Bias Limits**: Transmembrane voltage biases generated by the MCP4822 DACs are bounded by hardware rails. Software limits should never attempt to override safe operational ranges ($-1.587\text{ V}$ to $+1.587\text{ V}$).
2. **Weep-Moat Leak Detector Interlock**: The conductive weep sense moat detects saline electrolyte ingress into the flowcell cartridge. When triggered, the hardware interlock actively drops the $1.8\text{ V}$ analog power rail and halts peristaltic motor drivers (`DRV8837C`) to prevent thermal or chemical damage.
3. **Firmware DMA Bounds**: ADC DMA transfers write strictly to bounded circular ring buffers. Packet serialization enforces CRC-16-CCITT checksum validation to prevent malformed telemetry injection.
4. **Local Network Exposure**: In Wi-Fi Access Point mode, the device operates on a local non-routable subnet (`192.168.4.1`). If connecting the reader to enterprise or campus networks, isolate the device on a dedicated lab VLAN.
