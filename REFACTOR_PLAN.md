## 1. Target design (decisions already made)

| Topic | Decision |
|---|---|
| Pogo pins | Multi-pin **coax-style** (signal pin + guard/shield pins). **~7 mm** pin (LCSC C5221285 / YTC1P-6030-01, 9.0 mm free / 7.5 mm working / 2.0 mm base is the current candidate; confirm). |
| Amplifier board | **All pins on the component side** (`F.Cu`). Board is mounted **flipped** in the stack, so the pins point down at the interposer. Parts sit up and away from liquid. The only wet risk is wicking up the pins. |
| Interposer | Mating ENIG pads for every pin. Silver strips soldered to ENIG pads in the fluid path. Fluid path is an **X**. Cis = top face (faces the amplifier), Trans = bottom face. |
| Gaskets | **Same gasket on both sides** of the interposer. One of them captures the nanopore wafer. Channels must touch the interposer. They may or may not touch the pusher plates. |
| Fluidics | 4 fittings screwed into a plate, flush, pressing on the gasket for a liquid-tight seal. Flow enters from the bottom. Cis H1→H2, Trans H3→H4. |
| Spacers | Up to two: solid **polypropylene (PP)** block and a **3D-printed** spacer. They give height adjustment to match the pin stroke. |
| Rebuild | One command regenerates CAD, footprints, interposer PCB, amplifier pin placement, exports, and checks. |

### Resolved decisions (user answers, 2026-11-01)
1. **Keep all 12 pins (P1-P12).** Rings on the Interposer can't float: each ring net is fed across the air gap by dedicated pogo pins. Flanking guard pins also form a 3D driven guard cage around the exposed pin barrels.
   - **Coax footprint:** Pad 1 = center signal pad (circle or square), Pad 2 = concentric ring (`GUARD`, `GUARD_WIDE` or `GNDA`).
   - **Ring feeders (`RING_FEEDERS` in the spec):** `GUARD` ← P4, P6 (ring on P5). `GUARD_WIDE` ← P3 (ring on P2). `GNDA` ← P1, P10, P12 (rings on P7, P8, P9, P11).
   - The Pad 1 = signal / Pad 2 = ring convention should fix the baseline `P2` pad-number test failure (to verify in P4).
2. **Pin part:** C5221285 / YTC1P-6030-01, 9.0 mm free, 7.5 mm fully compressed. Checked by the gap budget in `stack_spec`.
3. **Spacers:** Delrin 0.125" (3.175 mm) and 0.270" (6.858 mm) stock blocks. PP 0.030" (0.762 mm) solid shim. A **3D-printed adjustable spacer** tunes pin stroke and gasket crush. Printed range is a **placeholder 0 to 3.0 mm** until confirmed.
4. **Legacy OpenSCAD:** frozen and disconnected, not deleted. Done (P6).

## 2. Baseline findings (audit, 2026-11-01)

`./scripts/run_python.sh scripts/generate_footprint.py` **runs** (about 2 s, exit 0). It is not "working as intended". Problems:

1. **Four sources of truth for pin coordinates.** `src/constants.py::POGO_DISTRIBUTED_PADS`, `PIN_NET_SEQUENCE*` in the script, `PogoPinHoles()` in `src/cartridge.py`, and hand-edited `.kicad_pcb` files. The script *imports* `POGO_Y` but hardcodes its own table.
2. **Y-axis and bank conventions disagree.** The script comments say Cis is `Y=-15` in some places and CAD `Y>0` in others. `POGO_Y = -15.0`. Cis/Trans naming per bank is inverted across the docstrings, `generate_6pin_*`, and the table.
3. **Stale pin-configuration experiments still emitted.** 6-pin Cis/Trans/Array targets, 6-pin "SpringHeader" (the "bottom-mounted" wording contradicts the flipped-amp design), `PogoPin_Target_6Pin_MillMax_09xx` (a duplicate of the 12-pin), and the Mill-Max 09xx descriptions (the BOM pin is LCSC C5221285).
4. **`generate_kicad_footprint` is a whole-board footprint.** It draws Edge.Cuts, fiducials, and fluid holes inside a *footprint*. The amplifier and interposer boards should be generated by board builders, with footprints only for pins and pads.
5. **`concentric_electrodes` is always empty.** `mold_radii` and `ribbon_pads_part` are computed and discarded (dead code). Fiducials are hardcoded.
6. **Fluid holes use a hardcoded `2.1` and `FLUID_PORT_X/Y` constants** that duplicate CAD. `extract_cad_geometry` is slow and fragile (it classifies wires by radius and edge-count heuristics).
7. **Footprint library sprawl.** Written to 4 directories (`Amplifier/footprints`, `Amplifier/footprints.pretty`, `Interposer/footprints.pretty`, `exports/footprints`). The default `--out` is not the cwd, but a stray `PogoPin_Target_6Pin_Distributed.kicad_mod` sits in the repo root (untracked).
8. **No pin-length / stack-height model.** Nothing ties the pin working height, spacer heights, gasket compression, and `TOTAL_STACK_HEIGHT` together. The CAD (`PTFE_Interposer`, `Rigid_Backing_Anvil`) and the PCB are therefore not guaranteed to agree.
9. **`extract_pin_positions_from_pcb`** is a regex over S-expressions. It is wrong for KiCad 8+ (`property "Reference"` rather than `fp_text reference`) and ignores rotation and flip.
10. **Legacy OpenSCAD** (`openscad-legacy/`, `test_legacy_*`, golden STL bounds) is coupled by tests and can inject stale geometry or fail on every change. `export_all.js` is already known-broken for the 2D DXFs.
11. **Stray files in the repo root and boards:** `PogoPin_Target_6Pin_Distributed.kicad_mod`, `Amplifier_old.*`, `Interposer_edit.kicad_sch`, `Amplifier-erc.rpt`, `stack layup.svg`. Decide what to keep or gitignore.
12. Test baseline: see *Status log* (full run recorded there).

## 3. Architecture (end state)

```
src/stack_spec.py   <- SINGLE SOURCE OF TRUTH (dataclasses; no build123d import; pure python)
   ├─ PogoPin spec: part no., free/working length, base pad, stroke, force
   ├─ PinMap: 12 (or N) pins: ref, net, role (signal/guard/shield), x, y, side (cis/trans), group
   ├─ Fluid: H1..H4 positions, drill, channel X topology, cis/trans mapping
   ├─ Stack: ordered layers with thickness, material, compression -> z-datums
   └─ Spacers: PP block, printed spacer, adjustment range, validate()
        │
        ├─ src/*.py (build123d CAD)  <- reads spec, builds stack from z-datums
        ├─ scripts/generate_footprint.py  <- reads spec only (no CAD solid queries)
        ├─ scripts/build_amplifier_kicad.py (new) <- places P1..Pn from spec on F.Cu
        ├─ scripts/build_interposer_kicad.py <- pads, strips, fluid holes from spec
        ├─ simulations/* and docs  <- read the same spec
        └─ tests/test_stack_consistency.py <- CAD == spec == PCB (parse .kicad_pcb)
scripts/rebuild_all.py  <- one command: spec validate -> CAD -> footprints -> PCBs -> checks -> exports
```

Rule: **CAD is derived from the spec; so are the footprints and boards. Nothing is read back from a hand-edited board** except through an explicit `--import-pcb` that *updates the spec*.
